# Сотрудники 66bit

Тестовое задание Frontend (React): SPA со списком сотрудников компании и их профилями, светлой и тёмной темой.

- **Список сотрудников** — поиск по ФИО, фильтры по должности, полу и стеку технологий, бесконечная подгрузка при прокрутке.
- **Профиль сотрудника** — фото, должность, стек и основная информация.

Вёрстка — по [макету в Figma](https://www.figma.com/design/uXmGUOCzotvGT2qwnDIz6W/66.Тестовое-для-Frontend-разработчика--Copy-?node-id=0-1) (десктоп и мобильная версия, обе темы). Данные — из [API](https://frontend-test-api.stk8s.66bit.ru/swagger/index.html).

## Запуск

Нужен Node.js 20.19+ или 22.12+ (требование Vite 8).

```bash
npm install
npm run dev
```

Приложение откроется на http://127.0.0.1:5173. Запросы к API идут через прокси Vite (`/api` → `frontend-test-api.stk8s.66bit.ru`), поэтому смотреть приложение нужно через dev-сервер или `npm run preview`.

| Команда                           | Что делает                                        |
| --------------------------------- | ------------------------------------------------- |
| `npm run dev`                     | Dev-сервер с горячей перезагрузкой                |
| `npm run build`                   | Проверка типов и production-сборка в `dist/`      |
| `npm run preview`                 | Просмотр production-сборки                        |
| `npm run lint`                    | ESLint                                            |
| `npm run format` / `format:check` | Форматирование Prettier / проверка форматирования |

## Стек

React 19, TypeScript (strict), Redux Toolkit (slices + RTK Query), React Router 7, SCSS modules, Vite, ESLint + Prettier. UI-библиотеки не используются.

## Структура

```
src/
  app/          store и типизированные хуки Redux
  features/     бизнес-логика по фичам
    employees/  RTK Query API, типы, форматирование, хук списка
    filters/    слайсы фильтров, селекторы, URL/LocalStorage, обработчики
    theme/      слайс темы и её применение к странице
  components/   презентационные компоненты (получают данные через пропсы)
  pages/        страницы-контейнеры: связывают фичи и компоненты
  hooks/        общие хуки: debounce, закрытие по клику снаружи, бесконечный скролл, синхронизация URL
  styles/       глобальные стили, цвета тем, миксины раскладки
  assets/icons/ иконки из макета
```

## Как это устроено

**Состояние.** Все сетевые запросы — через RTK Query (`features/employees/employeesApi.ts`): список — `infiniteQuery`, профиль — обычный `query`. В слайсах хранится только внутреннее состояние: фильтры, какой фильтр открыт, тема. Всё, что можно вычислить (аргумент запроса, чипы выбранных фильтров), считается селекторами.

**Кэш и запросы.** Данные считаются актуальными 5 минут (`keepUnusedDataFor` и `refetchOnMountOrArgChange`): повторный заход на профиль или возврат к списку не делает запросов. Поиск и фильтры применяются с задержкой 300 мс, чтобы не отправлять запрос на каждую букву. Query-string строится с фиксированным порядком параметров и без пустых значений.

**Фильтры.** Сохраняются в LocalStorage и синхронизируются с адресной строкой через `replace` (без новых записей в истории). При открытии страницы фильтры берутся из URL, если они там есть, иначе из LocalStorage. Некорректные значения отбрасываются. Dropdown закрывается по клику снаружи, Escape, уходу фокуса и при открытии другого фильтра, управляется с клавиатуры.

**Таблица.** Каждая ячейка строки — ссылка на профиль, растянутая на всю ячейку: работает клик по всей строке, Ctrl/Cmd+клик, средняя кнопка мыши и «Открыть в новой вкладке».

**Тема.** Выставляется inline-скриптом в `index.html` до загрузки React, поэтому нет вспышки другой темы. Переключение плавное (0.4 с), выбор сохраняется в LocalStorage. Без сохранённого выбора используется системная тема.

**Ошибки.** Отдельные экраны для несуществующей страницы (404), некорректного ID, ненайденного сотрудника, отсутствия соединения (с кнопкой повтора) и пустого списка. Непредвиденные ошибки рендера ловит `ErrorBoundary`, шапка при этом продолжает работать.

**Ререндеры.** Презентационные компоненты обёрнуты в `React.memo`, обработчики стабильны (`useFilterHandlers`, `useCallback`), производные данные — в `useMemo` и мемоизированных селекторах.

## Отступления от макета и задания

- **Кнопка «Найти».** Фильтры применяются автоматически; кнопка и Enter в поиске применяют их сразу, не дожидаясь задержки.
- **Fullstack.** В макете есть такая должность, но в API её нет, поэтому в фильтре пять должностей из Swagger.
- **Пол в профиле.** В макете поля нет, но задание требует показывать всю информацию о сотруднике.
- **Ошибка сети.** Показывается отдельным экраном с повтором запроса, а не через `ErrorBoundary`: RTK Query хранит ошибку в кэше, и после сброса boundary страница сразу упала бы снова, не повторив запрос.
- **Даты и телефоны** приводятся к виду из макета: `02 октября 1994` → `02.10.1994`, скобки в телефоне убираются.
